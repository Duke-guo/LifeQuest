# LifeQuest 架构与数据设计文档

> 状态：已确认（对齐 `AGENT.md` 后落档）
> 原则：先文档、后代码；本文档是后续开发的唯一数据契约，改数据模型必须先改本文档并取得确认。

## 1. 概述

LifeQuest = 本地优先的生活管理工具（日记 / 日历 / 待办 / 笔记 / 活动计划），游戏化是可选外壳，不制造焦虑。

核心设计原则（引自 `AGENT.md`）：
1. 本质是工具，功能优先。
2. 游戏化可配置、可关闭。
3. 失败不惩罚，不制造 FOMO。
4. 本地优先、隐私第一、数据可导出。
5. 低摩擦记录。
6. 模块化，先 MVP，不范围蔓延。
7. 先写文档，再写代码。

## 2. 技术栈（已确认）

| 项 | 选择 |
|---|---|
| 桌面壳 | Electron（Windows 本地桌面应用） |
| 前端 | Vue 3 + Vite + TypeScript |
| 包管理 | npm |
| 本地存储 | 文件夹 = Markdown + JSON |
| 版本控制 | Git |
| AI（后续可选） | DeepSeek API |

## 3. 架构分层

```
┌──────────────────────────────────────────────┐
│ 渲染进程（UI）：Vue 组件 / 主题样式 / 动画       │
├──────────────────────────────────────────────┤
│ 主进程（逻辑）：窗口管理 · IPC · 文件读写 · 导出  │
├──────────────────────────────────────────────┤
│ 数据层：统一数据模型 + 本地文件夹读写 + 版本迁移   │
├──────────────────────────────────────────────┤
│ 基础层：配置 / 主题 / schema 迁移 / 更新机制     │
└──────────────────────────────────────────────┘
```

- 渲染进程**不直接碰文件系统**，统一通过 `preload` 暴露的白名单 API 走 IPC 到主进程，保证数据读写唯一入口。
- 主进程是唯一有 `fs` 权限的一方，便于集中做版本迁移、备份、导出。

## 5. 数据设计（数据契约）

### 5.1 数据根目录

- 默认：系统「文档 / LifeQuest /」（Windows 用户文档目录）。
- 可在「设置」中更改；首次启动自动创建。
- 原则：**所有数据都是普通文件，程序外可直接打开、编辑、复制、备份。**

### 5.2 文件夹结构

```
LifeQuest/
├── config/
│   ├── settings.json        # 应用设置（含游戏化开关占位）
│   ├── seasons.json         # 赛季列表
│   └── achievements.json    # 内置成就 / 称号
├── tasks/
│   └── tasks.json           # 全部任务（主线 / 支线 / 每日）
├── journal/
│   └── 2025-09-15.md        # 每日日记 / 复盘（按日期命名）
├── notes/
│   └── *.md                 # 笔记（标签存 front matter）
├── plans/
│   └── *.json               # 活动计划
├── archive/
│   └── 2025-fall-回顾.md     # 已结束赛季的回顾快照
└── assets/                  # 图片 / 附件
```

### 5.3 通用约定

- **文本 → Markdown**，元数据用 YAML `front matter` 存。
- **结构 → JSON**，每个 JSON 文件**必须**含 `schemaVersion` 字段。
- 日期统一 ISO 8601 `YYYY-MM-DD`；时间戳 `YYYY-MM-DDTHH:mm:ss`。
- 所有字段为可扩展：读旧数据遇未知字段应忽略，写数据不删除他人手改的内容（最小破坏）。

### 5.4 各文件 Schema 与示例

#### config/settings.json

```json
{
  "schemaVersion": 1,
  "dataRoot": "",
  "theme": "default",
  "animations": { "enabled": true },
  "gamification": { "enabled": true, "level": "light" }
}
```

> `gamification.enabled` 是「可关闭」的预留开关（关闭的具体程度待定，但结构先留好）。

#### config/seasons.json

```json
{
  "schemaVersion": 1,
  "seasons": [
    {
      "id": "2025-fall",
      "name": "大一上学期",
      "type": "main",
      "start": "2025-09-01",
      "end": "2026-01-15",
      "status": "active",
      "categories": ["打卡计划", "期中考核", "期末考核"]
    },
    {
      "id": "2025-winter",
      "name": "寒假",
      "type": "side",
      "start": "2026-01-16",
      "end": "2026-02-20",
      "status": "planned",
      "categories": []
    }
  ]
}
```

- `type`：`main` = 主线赛季（如学期），`side` = 支线赛季（如假期）。
- `status`：`planned | active | archived`。
- `categories`：预置类别（是否打卡计划、是否有期中/期末考核等），驱动成就判定与称号。

#### config/achievements.json

```json
{
  "schemaVersion": 1,
  "achievements": [
    {
      "id": "checkin-7",
      "name": "打卡达人",
      "category": "打卡计划",
      "condition": { "type": "checkin_count", "value": 7 },
      "title": "打卡达人",
      "reward": { "xp": 50 }
    }
  ]
}
```

- `condition.type` 取值：`checkin_count`（累计打卡）、`task_count`（完成任务数）、`note_count`（笔记数）、`custom`（用户自定义）。
- `title` 用于「XX 达人」类称号展示。

#### tasks/tasks.json

```json
{
  "schemaVersion": 1,
  "tasks": [
    {
      "id": "t-0001",
      "type": "main",
      "title": "高等数学期中复习",
      "description": "",
      "importance": 4,
      "status": "todo",
      "seasonId": "2025-fall",
      "parentId": null,
      "due": "2025-10-25",
      "tags": ["学习", "考试"],
      "createdAt": "2025-09-15T08:00:00",
      "completedAt": null
    }
  ]
}
```

- `type`：`main`（主线/学期大目标）| `side`（支线/假期临时）| `daily`（每日打卡）。
- `importance`：1–5，用户自定义重要程度，映射到视觉醒目度（见 §7.4）。
- `status`：`todo | doing | done | archived`。
- `parentId`：支线可挂到主线之下，形成任务层级。

#### notes/*.md（笔记）

```markdown
---
date: 2025-09-15
theme: [学习, 高数]
rating: 4
tags: [重点]
---

笔记正文（Markdown）……
```

- `theme`：主题标签（可多个）；`rating`：评价标签（1–5）；`date`：日期标签。
- 这是「日期 / 主题 / 评价」三类标签系统的落点。

#### journal/YYYY-MM-DD.md（日记 / 复盘）

```markdown
---
date: 2025-09-15
mood: 4
tags: [复盘]
---

今日复盘正文……
```

#### plans/*.json（活动计划）

```json
{
  "schemaVersion": 1,
  "id": "p-0001",
  "title": "社团招新活动",
  "start": "2025-09-20",
  "end": "2025-09-20",
  "seasonId": null,
  "notes": "……",
  "taskIds": ["t-0002"]
}
```

### 5.5 版本与迁移

- 每个 JSON 文件带 `schemaVersion`。
- 启动时主进程读取各文件，`schemaVersion < 当前版本` 时按内置迁移函数逐级升级后写回（写回前先备份原文件到 `archive/backup/`）。
- 迁移失败时**不覆盖原数据**，报错并提示用户，绝不静默丢数据。

## 6. 功能模块设计

| 模块 | 职责 | 关键数据 | 依赖 |
|---|---|---|---|
| 日程 / 任务（核心） | 主线/支线/每日三级任务、重要度、状态流转 | tasks.json | 赛季 |
| 日历 | 日/周/月视图，与任务/日记联动 | tasks + journal | 任务、日记 |
| 笔记 | Markdown 编辑、三类标签、展开动画 | notes/*.md | 无 |
| 日记 / 复盘 | 每日记录、睡前复盘、与日历关联 | journal/*.md | 日历 |
| 活动计划 | 计划安排，可挂任务/赛季 | plans/*.json | 任务、赛季 |
| 游戏化 | 赛季、成就/称号、动画反馈、进度 | seasons + achievements + settings | 任务、赛季 |
| 回顾 / 总结 | 赛季回顾生成与展示 | archive/*.md | 全部 |
| 系统 | 设置、主题、导出/导入、更新 | settings.json | 无 |

> 模块之间只通过「数据层」和「服务层」通信，不互相直接引用，便于独立迭代。

## 7. 游戏化系统设计（轻 · 不焦虑 · 预留可关）

### 7.1 任务层级

- 主线任务（学期大目标）→ 支线任务（假期/临时）→ 每日任务（打卡）。
- 层级只用于**组织与反馈**，不产生强制关系；支线可不挂主线。

### 7.2 赛季

- 起止时间**用户自设**；`main` 为主线赛季，`side` 为支线赛季（假期）。
- 支持多赛季并存与归档；赛季是内容节奏，不是压力来源。

### 7.3 成就 / 称号

- 内置固定成就（`achievements.json`）+ 预置类别（`seasons.categories`：打卡计划、期中/期末考核…）。
- 按完成情况授予「XX 达人」称号；奖励只给不扣。

### 7.4 重要度 → 醒目度映射

| importance | 视觉表现 |
|---|---|
| 5 | 主题色高亮 + 置顶 + 强调动画 |
| 4 | 高亮 + 置顶 |
| 3 | 常规 |
| 2 | 弱化显示 |
| 1 | 灰显，收进「低优先」折叠 |

### 7.5 动画

- 笔记 / 安排表**展开动画**、任务**完成动画**、页面切换样式（参考洛克王国明快风格）。

### 7.6 明确不做

- 连续打卡惩罚、焦虑倒计时、红点轰炸、排行榜、强制任务、复杂战斗、重氪逼肝。

### 7.7 可关闭（预留）

- `settings.gamification.enabled` 全局开关；关闭后隐藏动画与成就/称号展示（具体隐藏程度待定，结构已预留）。

## 8. 赛季回顾设计

- 触发：赛季结束时自动 + 用户手动触发。
- 产出：`archive/<赛季id>-回顾.md` 快照，含：
  1. 统计数字（完成任务数、打卡天数、笔记数…）
  2. 时间轴回顾
  3. 成就 / 称号墙
  4. 亮点与待改进

## 9. 导出 / 导入

- 数据本身是开放文件，**导出 = 一键打包为 zip 或复制到指定目录**；**导入 = 反向读回**。
- 迁移 = 直接复制 `LifeQuest/` 文件夹。

## 10. MVP 范围与分期

- **P0** 项目骨架（Electron + Vite + Vue3 + TS + npm）跑通。
- **P1** 数据层：文件夹读写 + 版本迁移 + 导出。
- **P2** 日程/任务 + 日历（核心）。
- **P3** 笔记 + 日记/复盘。
- **P4** 赛季/游戏化：任务层级 + 动画 + 基础成就/称号。
- **P5** 设置/导出/赛季回顾 + 联调验证。

## 11. 未来扩展点（不进 MVP）

- 多设备同步（数据开放，天然可接入）。
- AI 生成成就/任务建议（DeepSeek API，作为可选服务挂入）。
- 游戏化「可关闭」的细化。
- 场景模板（学习 / 工作 / 假期）在应用内自定义。
