# 成就与回顾系统设计（方案稿 · v1）

> 本文是设计方案，不涉及代码。目标是回答两件事：
> 1. 现在的成就系统到底缺什么；
> 2. 怎么把它和「生成回顾」升级成有温度、但不制造焦虑的体验。
>
> 设计红线（来自产品基调）：**无排名、无连击、无「落后」焦虑；本地优先、可整体关闭；成就是「镜子」，不是「鞭子」。**

---

## 1. 现状诊断

### 成就系统（`stores/gamification.ts` + 赛季页）
- 只有 **4 个写死的计数器**：任务达人(5)、打卡达人(7 每日)、笔记达人(3)、复盘达人(3 日记)
- **全局累计，不跟赛季挂钩**，也分不清「这个学期」和「上个学期」
- 目标太低且一成不变，几天就全部达成，之后没有新东西
- 成长表达只有 `Lv.x · N XP`，冷冰冰，像网游而非生活记录

### 生成回顾（`SeasonsView.generateReview`）
- 点按钮 → 落盘 `LifeQuest-Data/archive/<赛季id>-回顾.md`，**应用内不显示预览**，只有一句「已生成」
- 内容：统计 + 4 个成就勾选 + 完成时间轴 + **两句写死的评语**
- 没有「人味」：不引用你自己的话，也抓不住这一季真正发生了什么

---

## 2. 目标体验

用户打开赛季页，看到的应该是「**这一季我留下了什么**」，而不是「我得了多少分」。

| 现在 | 目标 |
|---|---|
| 4 个数字徽章 | 一层层被点亮的「你做到了什么」 |
| Lv.x · XP | 称号 / 记录密度，纯氛围 |
| 一句「回顾已生成」 | 应用内结算页 + 一键存 md |
| 两句写死评语 | 高光时刻 + 你自己的原话 |

---

## 3. 成就系统方案

### 3.1 三层成就（混在一起，但来源不同）

| 层 | 含义 | 例子 | 谁定义 |
|---|---|---|---|
| **里程碑成就** | 系统自动识别「第一次/做到过」，达成后永久点亮 | 第一次把笔记关联到任务、第一次 AI 识图导入课表、连写 3 天日记 | 系统内置 |
| **赛季成就** | 只统计本季数据，赛季结束结算 | 本学期完成 10 个任务、写了 5 篇日记、笔记满 3 篇 | 系统内置，按赛季算 |
| **自定义成就** | 用户自己写的目标 | 「这学期读完 3 本闲书」 | 用户自建 |

### 3.2 数据模型草案（仅示意，不实现）

```
Achievement {
  id            // 唯一 id
  name / desc   // 名称与一句说明
  kind          // 'milestone' | 'season' | 'custom'
  seasonId?     // 赛季成就才需要
  target        // 达成阈值（进度 >= target 点亮）
  progress()    // 纯函数：从本地数据实时算出，不存盘、不联网
  icon          // 用 AppIcon 现有图标
  unlockedAt?   // 首次达成时间（里程碑需要；赛季成就在结算时写）
}
```

**关键点：进度永远实时算**，不写死、不需要同步服务器——打开页面时从 `tasks.json / notes/ / journal/` 现算，天然本地优先。

### 3.3 里程碑成就清单（建议首版 ~12 个，够丰富又不堆砌）

**生活记录**
- 第一缕晨光：写第 1 篇日记
- 七日回响：日记满 7 篇
- 生活史官：日记满 30 篇

**任务**
- 迈出第一步：完成第 1 个任务
- 主线推进者：完成第 1 个主线任务
- 收官：把一个赛季的任务全部完成

**笔记 / 知识**
- 第一页：写第 1 篇笔记
- 织网者：第一次把笔记「关联」到任务
- 知识管家：笔记满 10 篇

**探索（把冷门功能变有趣）**
- 识图者：第一次用 AI 识图导入课表
- 时光旅人：第一次从主线地图的锚点跳回日记
- 布局师：第一次给日历手动指定某天的性质（上课/放假/考试…）

### 3.4 明确不做（写进代码评审红线）

- ❌ **连击 / 断签惩罚**——漏一天没有任何代价
- ❌ **排行榜、好友比较、分享**——本地单机
- ❌ **每日推送「该打卡了」**——提醒只服务于日程，不服务于成就
- ❌ **数字等级膨胀**——Lv 可以留着，但弱化成装饰，不是主视觉

## 4. 成长表达（替掉冷冰冰的 Lv/XP）

### 4.1 称号
按「你留下的东西」给一个头衔，而非数字：

| 数据 | 称号阶梯 |
|---|---|
| 日记 0→7→30 | 过客 → 记录者 → 生活史官 |
| 笔记 0→3→10 | 空手 → 整理师 → 知识管家 |
| 完成任务 0→5→20 | 新人 → 行动派 → 收官者 |

主页/赛季页顶部展示当前称号，语气是「你现在是 **生活史官**」，不是「你才 3 级」。

### 4.2 记录密度折线（首页）
一张很小的「本周你留了多少记录」折线（日记+笔记+完成任务），替代 XP 数字。它只反映「存在感」，不反映「成绩」。

## 5. 生成回顾升级方案

### 5.1 回顾 v2 内容（每一块都有温度）

1. **概览卡**：赛季名、起止、类型、一句总括（如「这学期你留下了 27 篇日记、11 条主线」）
2. **高光时刻**（自动挑，不是写死）：
   - 最忙的一周 / 最闲的一周
   - 笔记最多的一天
   - 完成率最高的一周
3. **你的一句话**：从该赛季日记里随机抽一句（或最长的一篇里挑一句），署上日期
4. **成就清单**：三层成就各自「已点亮 / 进行中 x/y」
5. **完成时间轴**：保留现有，但补上「这件事属于哪个赛季」
6. **下一步**（可选、非评判语气）：「还有 N 个进行中的任务，不急，慢慢来」

### 5.2 交互：应用内预览 → 一键存盘

- 点「生成回顾」→ 弹出**结算页预览**（动画逐个点亮成就）→ 底部两个按钮：
  - **保存为 Markdown**（沿用 `archive/<赛季id>-回顾.md`，格式升级）
  - **复制全文**（方便贴到别处）
- 结算页也支持从赛季列表点「查看回顾」重新打开（读回已存的 md 或现算）

## 6. 数据落盘（不破坏现有数据）

| 内容 | 存储 | 说明 |
|---|---|---|
| 里程碑 / 赛季成就 | 运行时计算，`unlockedAt` 写进一个小的 `config/achievements.json` | 只记「何时点亮」，进度仍现算 |
| 自定义成就 | `config/achievements.json` | 用户自建，随数据走 |
| 回顾 | `archive/<赛季id>-回顾.md` | 沿用现路径，内容升级 |
| 日记原话抽取 | 现读 journal/ | 不额外存 |

老数据完全兼容：没有 `achievements.json` 时按空处理，成就照常现算。

---

## 7. 分阶段实施（建议顺序）

| 阶段 | 内容 | 改动面 |
|---|---|---|
| **P0** | 「生成回顾」应用内预览弹窗 + 高光时刻 + 日记原话 | 只动 SeasonsView + 一个回顾弹窗组件 |
| **P1** | 成就改按赛季统计 + 里程碑成就 + 称号 | gamification store + 赛季页 + 首页称号 |
| **P2** | 自定义成就 + 首页记录密度折线 | 新增编辑器 + 首页小组件 |

P0 无依赖，可独立上线；P1 依赖 P0 里拆出的「回顾内容生成」纯函数。

---

## 8. 已拍板的决策（2026-10-12）

1. **称号风格**：走「生活史官」这种正经方向 ✓
2. **自定义成就**：要 ✓（已实现：任务/每日打卡/笔记/日记 四个维度 + 目标数）
3. **回顾触发**：手动点「生成回顾」，结果**直接在应用里弹窗显示**，并可「保存为 Markdown / 复制全文」✓
4. **Lv/XP 去留**：**称号为主，Lv/XP 缩到角落**当装饰 ✓
